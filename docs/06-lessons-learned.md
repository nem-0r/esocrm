## Telegram / MTProto

**Нет статуса «доставлено».** MTProto не даёт признак delivered для сообщения. В прошлой версии
он был заложен в спеку и потом вычеркнут как нереализуемый. Не обещать его в UI и не закладывать
в модель данных. Прочитано/непрочитано — есть, доставлено — нет.

**Rate limits и FloodWait.** Личные аккаунты банятся за резкую активность. Любая массовая
операция (первичная синхронизация истории, рассылка) должна идти через очередь с бэкоффом,
а не циклом.

**Telethon работает исходящими соединениями** — публичный IP и проброс портов не нужны,
интеграцию можно тестировать локально на макбуке. Первым подключать личный или запасной номер,
не рабочий.

**Сессии Telethon — это секрет.** Файл сессии = полный доступ к аккаунту. Шифровать, не класть
в git, не в образ.

## Деньги и данные

**Гонки на платежах.** Параллельные операции по одной сделке разъезжаются. Нужен
`SELECT ... FOR UPDATE` на сделке при записи платежа/возврата.

**Снапшоты сумм.** Суммы и реквизиты на момент операции нужно фиксировать в платеже, а не
пересчитывать из текущего состояния справочников — иначе задним числом «меняется история».

**Обход бизнес-правил через смену статуса.** Был дефект: правило «оплаченную сделку нельзя
менять» обходилось сменой статуса. Проверять инварианты на переходах состояний, а не на полях.

**Форматы.** Деньги — целые тенге, `> 0`, `≤ 100 000 000`. Даты в API — ISO `ГГГГ-ММ-ДД`.
Значения из справочников валидировать по справочнику целиком, а не по подстроке (реальный
случай: в базе «Перевод по номеру телефона», код ждал «Перевод по номеру»).

**Formula injection в CSV.** Значения, начинающиеся с `=`, `+`, `-`, `@`, Excel исполняет как
формулу. Экранировать при экспорте. (В прошлой версии осталось незакрытым.)

## Права и аутентификация

**Чужая сущность = 404, не 403.** 403 подтверждает, что запись существует. Реальные дефекты
прошлой версии: утечка карточки клиента менеджеру; `500` вместо `404` на несуществующем клиенте
у admin.

**Логин регистронезависим.** Блокировка по логину обходилась сменой регистра (`Ivan` vs `ivan`).
Нормализовать логин до сравнения — и при входе, и при блокировке.

**bcrypt блокирует event loop.** В async-приложении хеширование пароля нужно уносить в
threadpool, иначе один вход подвешивает весь сервер.

**Гонка при создании пользователей** — двое с одинаковым логином. Advisory lock или уникальный
индекс + обработка конфликта.

**Cookie в продакшене** — обязательно `Secure` + `HttpOnly` + `SameSite`. В прошлой версии
`Secure` однажды забыли.

## Фронтенд

**Фронт молча подменял 401 моками.** Самый коварный класс багов: сервер отвечает «не авторизован»,
а интерфейс показывает демо-данные, и всё «работает». Мок-режим и боевой режим не должны иметь
общего кода отката. Ошибка обязана быть видимой.

**Мок-сборка уехала в «прод».** `COPY dist` с хоста однажды затащил в продакшен-образ сборку
с моками — руководитель увидел чужой дашборд. **Правило: Dockerfile многоэтапный, фронт
собирается ВНУТРИ образа с боевым флагом API.** Никаких `dist` с хоста.

**SPA-fallback на Starlette.** `StaticFiles` **бросает** `HTTPException(404)`, а не возвращает
ответ — обработчик fallback нужно писать с учётом этого, иначе глубокие ссылки ломаются.

## Производительность

Наивные запросы не держат 50k клиентов / 1M сообщений. Что помогло в прошлой версии:
поиск переписан на `EXISTS` (550→300 мс), дашборд получил индекс (671→349 мс),
`shared_buffers=512MB` в Postgres. Импорт клиентов остался медленным (~7 мс/строка) —
делать пакетно, а не построчно.

## SLA

**Рабочие минуты ≠ календарные.** Считали в рабочих часах, а в подписях интерфейса показывали
календарные — цифры не сходились, и это выглядело как баг расчёта. Одна единица измерения
сквозь весь стек, и она должна быть подписана в UI.

**Идемпотентность планировщика.** Повторный запуск задачи не должен плодить дубликаты нарушений —
привязка к идентификатору события (в прошлой версии: `trigger_message_id`).

**Демо-данные + SLA-движок несовместимы.** На демо-сиде с намеренно просроченными диалогами
планировщик генерирует лавину ложных нарушений. Либо сид, либо движок.

## Тесты и окружение

**Сид-тесты стирали рабочую БД.** Тестовая база должна быть физически отдельной, и тест обязан
падать, если подключился не туда, а не «на всякий случай» чистить.

## Внешние инструменты (справочно)

**Figma MCP (`use_figma`).** Главный баг: `resize()` **после** `layoutSizing = FILL` сбрасывает
режим в `FIXED` — сначала resize, потом FILL. `createAutoLayout` даёт белую заливку — обнулять
`fills = []`. На тарифе Starter есть burst-лимит ~20 вызовов подряд, дальше отказ; помогает
пауза в несколько минут. Установлены плагины `figma` и `designagent`.

## Грабли этой версии (2026-08-28)

**Postgres-перечисления хранят имена, а не значения.** `Enum(MyEnum, native_enum=True)` в
SQLAlchemy по умолчанию создаёт тип со значениями `PENDING`, `CONNECTED`, а `server_default`
мы пишем строчными — и первая же миграция падает на `invalid input value for enum`.
Лечится `values_callable=lambda e: [m.value for m in e]` во всех Enum-колонках.
У нас это вынесено в `enum_values` в `app/models/enums.py`.

**Столбец `text` затеняет `sqlalchemy.text` внутри тела класса.** В `Message.text` и
`Template.text` объявление колонки перекрывает импортированную функцию, и `Index(..., text("..."))`
падает с `'MappedColumn' object is not callable`. Импортировать как `text as sa_text`.

**Два внешних ключа на одну таблицу требуют явного `foreign_keys`.** В `account_managers`
есть `user_id` и `assigned_by_id`, оба ссылаются на `users`. Без `foreign_keys` в
`User.account_links` SQLAlchemy не может выбрать сторону связи и роняет **каждый** ORM-запрос
с `AmbiguousForeignKeysError` — включая вход. Симптом обманчивый: сервер отвечает 500 на
`/auth/login`, и кажется, что дело в аутентификации.

**Загруженный файл и строка в базе — разные вещи.** Эндпойнт загрузки кладёт файл в хранилище
и возвращает ключ, но строку `attachments` создаёт только отправка сообщения — в одной
транзакции с ним. Иначе в базе копятся вложения без владельца, а в очередь уходит пустое
сообщение. Контракт между загрузкой и отправкой надо фиксировать заранее: у нас на этом
разъехались два независимо написанных куска.

**Кэш npm, испорченный `sudo`.** Если когда-то запускали `sudo npm`, часть
`~/.npm/_cacache` принадлежит root, и установка падает с `EEXIST` и `EACCES` на rename.
Обходится локальным кэшем через `.npmrc`, чинится `sudo chown -R $(id -u):$(id -g) ~/.npm`.

**Порт 6379 занят локальным Redis.** Если Redis стоит через brew, контейнер не поднимется.
В `docker-compose.yml` он проброшен на 6380 — внутри сети сервисы всё равно ходят на 6379.
