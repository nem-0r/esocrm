## Контур Telegram: написан целиком, ждёт ключей

Приёма входящих больше не «нет вообще» — он есть и проверен 22 автоматическими
проверками. Что появилось 2 сентября:

- `app/services/inbound_service.py` — единственная дверь для входящих: дедупликация
  по `(диалог, tg_message_id)`, автосоздание карточки клиента и диалога, счётчики,
  события в интерфейс. Через неё же идут ответ менеджера с телефона, работа воронки
  и подтяжка истории.
- `telegram_peers` — хранилище `access_hash` парой «аккаунт + собеседник».
- `app/core/command_bus.py` — канал команд из API в шлюз через Redis: вход в аккаунт,
  подтяжка истории, отметка о прочтении. Строка сессии наверх не возвращается —
  шлюз шифрует и сохраняет её сам.
- `app/gateway/mtproto_provider.py` — боевой провайдер на Telethon: приём, отправка,
  история, FloodWait как расписание, потеря сессии как состояние аккаунта.
- `POST /accounts/{id}/sync-history` — подтяжка переписки, идёт фоном.

Не хватает трёх вещей, которые нельзя написать кодом: `api_id`/`api_hash`,
самих номеров и мобильных прокси (по одному на аккаунт, решение D-21).
