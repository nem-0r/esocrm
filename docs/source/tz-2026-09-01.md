## 2. Чаты с клиентами

### 2.1. Плашка «Ожидают ответа»
- Плашка должна исчезать после того, как менеджер открыл и просмотрел чат.
- Плашка по итогам ожидания ответа должна срабатывать **только один раз**.

### 2.2. Краткая информация в чате
Строка должна содержать по порядку: название аккаунта, направление клиента,
статус оплаты, ответственный менеджер, срок клиента.

```
Астро | Первые продажи | Оплат пока нет | Ведёт: Иван | Клиент с 22 мая 2026
```

Названия аккаунтов: «Астро», «Изабель Архетип», другие направления.
Направления: «Бот», «Первые продажи», «Допы».

### 2.3. Сделки по аккаунтам
- Показывать количество сделок **только по конкретному аккаунту**.
- Сделки с других аккаунтов не учитывать.

### 2.4. Служебные заметки
- Сейчас служебные заметки в чате видят все пользователи.
- Определить, должно ли быть ограничение доступа. **(вопрос, не задача)**

## Конфликты с ранее принятыми решениями

Требуют решения владельца до начала работ.

### Сервер вне России против 152-ФЗ

Пункт 7.2 требует нероссийский сервер. Решение **D-09** говорит обратное:
персональные данные граждан РФ (телефон, дата и место рождения) по 152-ФЗ должны
храниться в базе на территории России.

Разрешается разделением: база с персональными данными — в России, шлюз MTProto —
где угодно, он данные не хранит. Если же имеется в виду именно база вне РФ, это
юридический риск, и решать его должен не разработчик.

Отдельно: сервер вне России **не защищает Telegram-аккаунты от блокировки** —
там важен тип адреса, а не страна (решение **D-21**).

### Глубина истории: фиксированная дата вместо срока

Пункт 4.2 задаёт «с 1 января 2026». В системе настройка `history_sync_days`
измеряется в днях (сейчас 365). Нужно либо менять тип настройки на дату,
либо пересчитывать дни от 1 января. Второе проще и переживёт смену года.

### Шаблоны убрать из MVP

Пункт 3.1. Шаблоны уже построены и работают: справочник, личные и общие,
подстановка в поле ввода. Убирать — значит прятать готовое. Предлагаю скрыть
кнопку, а код и таблицу оставить: вернуть будет одним переключателем.

### Код платежа убрать из окна создания

Пункт 4.3. Код платежа равен номеру сделки и нужен клиенту для сверки перевода.
Убирается только **отображение в момент создания** — в отправленном счёте он
остаётся, иначе оплату по реквизитам нечем сверять.

### Вопрос по пункту 1.4

«Убрать блок Прогрев у менеджеров» допускает два прочтения:

1. Скрыть **подпись направления** под строкой чата — косметика.
2. Не показывать менеджерам **сами чаты** аккаунтов этапа «Бот» — это смена прав
   и заметно меняет их работу: сейчас Марина назначена на «Астра · бот».

Второе выглядит логичнее по смыслу (бот греет сам, менеджеру там делать нечего),
но это решение владельца, а не разработчика. Не трогал до ответа.
